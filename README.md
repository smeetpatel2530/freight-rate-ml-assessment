## Modeling approach

1. Use `train_test.csv` as labeled development data.
2. Validate chronologically instead of using a random split, because the final validation set is future data.
   - Development train: 2025-01-01 through 2025-08-31
   - Holdout: 2025-09-01 through 2025-10-31
3. Create route, calendar, cyclical time, geographic-difference, distance, weight, market, and quote interaction features.
4. Train a 3-seed CatBoost ensemble.
5. Model `posted_rate / (distance + 200)` and transform predictions back to dollars. This reduces the dominance of long-haul distance while still allowing the model to capture a fixed-cost component for short hauls.
6. Retrain on all 48,000 labeled rows and predict all 12,000 validation rows.
7. Train a separate reduced-feature CatBoost model for the fixed December chart because the supplied December input does not include coordinates, `market_index`, or `quote_signal`. No unavailable values are fabricated.

## Observed data-quality issues

- Training data: 300 missing `weight` values and 374 missing `market_index` values.
- Final validation data: 165 missing `weight` values and 249 missing `market_index` values.
- Eight pickup/delivery cities appear in final validation but not in training.
- CatBoost is used because it handles missing numeric values and previously unseen categorical values without requiring fragile one-hot schemas.

## Validation result from the temporal holdout

The generated `outputs/run_summary.json` records the exact run. On the supplied data, the CatBoost ensemble achieved approximately:

- MAE: **106.82**
- RMSE: **632.24**
- R2: **0.8284**
- MAPE: **4.80%**

A simple median-rate-per-mile-by-equipment baseline had MAE about **229.10**, so the final model reduced MAE by more than half on the future-style holdout.
